# T3 · Katalog-REST-Endpunkte

---

## Kontext

Nach T1 (Domain + Persistenz) und T2 (OpenLibrary-Suche) fehlt die verbindende Schicht: Application Services und ein REST-Controller, der beides nach außen exponiert. Derzeit kann kein Client den Katalog befragen oder befüllen – alle Klassen aus T1 und T2 liegen brach.

Ziel dieses Tickets ist es, den `catalog`-Kontext vollständig benutzbar zu machen: Ein `CatalogService` kapselt die Geschäftslogik der fünf Operationen (Suchen, Hinzufügen, Auflisten, Detailabruf, Entfernen). Ein `CatalogController` exponiert diese Operationen als REST-API unter `/catalog`.

Das ist das letzte Backend-Ticket vor dem Frontend (T4, T5). Nach T3 ist die gesamte Katalogfunktionalität über `curl` vollständig testbar.

### Was T1 und T2 bereitgestellt haben

| Klasse | Paket | Rolle in T3 |
|--------|-------|-------------|
| `CatalogBook` | `catalog.domain` | Wird in `CatalogService` per `add(...)` / `restore(...)` genutzt |
| `CatalogBookId` | `catalog.domain` | Wird für Pfadvariablen (`/books/{id}`) genutzt |
| `CatalogBookRepository` | `catalog.application.ports.out` | Output Port – wird in `CatalogService` injiziert |
| `LibrarySearchClient` | `catalog.application.ports.out` | Output Port – wird in `CatalogService` injiziert |
| `BookSearchResult` | `catalog.application` | Wird direkt als JSON-Antwort auf `GET /catalog/search` zurückgegeben |

## Aufgabe

### 1. `AddBookRequest` – Request-DTO

Record in `catalog/adapters/in/rest/dto/`. Wird vom Controller beim `POST /catalog/books` entgegengenommen. Felder entsprechen eins zu eins den Feldern von `BookSearchResult`, sodass das Frontend das Suchergebnis direkt weiterleiten kann – ohne Transformation.

```java
package de.demo.lending.catalog.adapters.in.rest.dto;

public record AddBookRequest(
        String isbn,
        String title,
        String author,
        String coverUrl,
        String openLibraryKey
) {}
```

Validierung: `title` darf nicht null/leer sein – wird von `CatalogBook.add()` geprüft und wirft `IllegalArgumentException`. Der Controller fängt diese ab und antwortet mit `400 Bad Request`.

### 2. `CatalogBookDto` – Response-DTO

Record in `catalog/adapters/in/rest/dto/`. Bildet einen Katalogeintrag für die JSON-Antwort ab. Enthält zusätzlich `id` (als `String`) und `addedAt`, die im `AddBookRequest` nicht vorhanden sind.

```java
package de.demo.lending.catalog.adapters.in.rest.dto;

import java.time.Instant;

public record CatalogBookDto(
        String id,
        String isbn,
        String title,
        String author,
        String coverUrl,
        String openLibraryKey,
        Instant addedAt
) {}
```

Mapping von `CatalogBook` → `CatalogBookDto` als private statische Methode im Controller oder im Service. Empfohlen: im Controller, da es eine reine Präsentationsverantwortung ist.

### 3. `CatalogService` – Application Service

Klasse in `catalog/application/`. Annotiert mit `@Service`. Kapselt alle Katalogoperationen. Empfängt `CatalogBookRepository` und `LibrarySearchClient` per Konstruktorinjektion.

**Methoden:**

| Methode | Signatur | Verhalten |
|---------|----------|-----------|
| Suchen | `List<BookSearchResult> search(String query)` | Delegiert an `LibrarySearchClient.search(query)` |
| Hinzufügen | `CatalogBookId add(AddBookRequest request)` | Ruft `CatalogBook.add(...)` auf, speichert per Repository, gibt `CatalogBookId` zurück |
| Auflisten | `List<CatalogBook> findAll()` | Delegiert an `CatalogBookRepository.findAll()` |
| Detailabruf | `Optional<CatalogBook> findById(UUID id)` | Delegiert an `CatalogBookRepository.findById(CatalogBookId.of(id))` |
| Entfernen | `void remove(UUID id)` | Delegiert an `CatalogBookRepository.deleteById(CatalogBookId.of(id))` |

`add()` ist mit `@Transactional` zu annotieren (schreibende Operation). Alle anderen Methoden sind lesend und benötigen keine Transaktion.

### 4. `CatalogController` – REST-Controller

Klasse in `catalog/adapters/in/rest/`. Annotiert mit `@RestController` und `@RequestMapping("/catalog")`. Empfängt `CatalogService` per Konstruktorinjektion.

**Endpunkte im Detail:**

```
GET /catalog/search?q={query}
```
- Parameter `q` als `@RequestParam String query`
- Aufruf: `service.search(query)`
- Antwort: `ResponseEntity.ok(results)` – auch leere Liste ist `200 OK`
- Kein 404 bei keinem Treffer (leere Liste ist ein valides Suchergebnis)

```
POST /catalog/books
```
- Body: `@RequestBody AddBookRequest request`
- Aufruf: `service.add(request)`
- Antwort: `ResponseEntity.status(201).body(Map.of("id", id.value().toString()))`
- Fehlerfall: `IllegalArgumentException` → `ResponseEntity.badRequest().body(Map.of("error", e.getMessage()))`

```
GET /catalog/books
```
- Aufruf: `service.findAll()`
- Mapping: `List<CatalogBook>` → `List<CatalogBookDto>` per Stream
- Antwort: `ResponseEntity.ok(dtos)`

```
GET /catalog/books/{id}
```
- Pfadvariable `@PathVariable UUID id`
- Aufruf: `service.findById(id)`
- Antwort: `200 OK` mit `CatalogBookDto` oder `404 Not Found` bei leerem Optional

```
DELETE /catalog/books/{id}
```
- Pfadvariable `@PathVariable UUID id`
- Aufruf: `service.remove(id)`
- Antwort: `ResponseEntity.noContent().build()` (`204`)

## Akzeptanzkriterien

- [ ] `AddBookRequest` und `CatalogBookDto` sind Java Records im Package `de.demo.lending.catalog.adapters.in.rest.dto`.
- [ ] `CatalogService` liegt im Package `de.demo.lending.catalog.application`, ist mit `@Service` annotiert und implementiert alle fünf Operationen.
- [ ] `CatalogController` liegt im Package `de.demo.lending.catalog.adapters.in.rest`, ist mit `@RestController` und `@RequestMapping("/catalog")` annotiert.
- [ ] `GET /catalog/search?q=Kafka` liefert eine JSON-Liste mit mindestens einem Treffer (Felder: `isbn`, `title`, `author`, `coverUrl`, `openLibraryKey`).
- [ ] `POST /catalog/books` mit einem gültigen JSON-Body legt ein Buch an und antwortet mit HTTP 201 und `{ "id": "..." }`.
- [ ] `GET /catalog/books` gibt nach dem POST alle gespeicherten Bücher zurück (JSON-Array).
- [ ] `GET /catalog/books/{id}` gibt das korrekte Buch zurück; eine unbekannte ID liefert HTTP 404.
- [ ] `DELETE /catalog/books/{id}` löscht das Buch und antwortet mit HTTP 204; ein anschließendes `GET /catalog/books/{id}` liefert 404.
- [ ] `POST /catalog/books` mit fehlendem oder leerem `title` antwortet mit HTTP 400.
- [ ] `mvn compile` läuft ohne Fehler.
- [ ] Die bestehende Demo-UI (`/demo/demo.html`) und der Loan-Flow funktionieren weiterhin unverändert.

## Nicht im Scope dieses Tickets

- Frontend (T4, T5, T6)
- Pagination bei `GET /catalog/books`
- Volltextsuche im eigenen Katalog (nur OpenLibrary-Suche ist in scope)
- Duplikat-Prüfung beim Hinzufügen (kein ISBN-Unique-Constraint)
- Authentifizierung / Autorisierung
- OpenAPI / Swagger-Dokumentation
