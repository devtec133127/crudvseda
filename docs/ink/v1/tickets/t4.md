# T4 · Frontend: Buchsuche

---

## Kontext

Nach T1–T3 ist die gesamte Backend-API des Katalogs fertig und per `curl` testbar. Es fehlt eine Benutzeroberfläche. T4 liefert die primäre Nutzer-Seite: eine Buchsuche über OpenLibrary mit Trefferanzeige, Detailansicht und der Möglichkeit, ein Buch in den eigenen Katalog zu übernehmen.

Das Projekt hat bereits eine Frontend-Seite (`/demo/demo.html`) – Vanilla JavaScript, Fetch-API, kein Framework. Dieses Muster wird für den Katalog 1:1 fortgeführt. Kein neues Build-Tool, kein npm, kein Framework.

### Ziel

Eine eigenständige HTML-Seite `search.html` unter `static/catalog/` mit zugehörigen Dateien `catalog.css` und `search.js`. Die Seite deckt den vollständigen Suchfluss ab:

```
Eingabe → Suche → Trefferliste → Detailansicht → In Katalog übernehmen → Bestätigung
```

### Verwendete API-Endpunkte (aus T3)

**Suche:**
```
GET /catalog/search?q={query}
→ 200 OK
[
  {
    "isbn": "9780132350884",
    "title": "Clean Code",
    "author": "Robert C. Martin",
    "coverUrl": "https://covers.openlibrary.org/b/id/8432581-M.jpg",
    "openLibraryKey": "/works/OL1820750W"
  }
]
```

**Buch übernehmen:**
```
POST /catalog/books
Content-Type: application/json
{ "isbn": "...", "title": "...", "author": "...", "coverUrl": "...", "openLibraryKey": "..." }
→ 201 Created
{ "id": "<uuid>" }
```

### Dateistruktur nach diesem Ticket

```
src/main/resources/static/
├── demo/
│   ├── demo.html   ← unverändert
│   ├── demo.js     ← unverändert
│   └── demo.css    ← unverändert
└── catalog/
    ├── catalog.css   ← NEU (gemeinsames CSS für T4 + T5)
    ├── search.html   ← NEU (diese Seite)

```

`catalog.css` definiert dieselben CSS-Variablen wie `demo.css` und ergänzt katalogspezifische Klassen. Es wird von `search.html` (T4) und `manage.html` (T5) eingebunden.

| `detailIsbn` | Element | ISBN |
| `addBtn` | `<button>` | „Übernehmen"-Aktion |

### 3. `search.js` – Seitenlogik

Neue Datei in `static/catalog/`. Kein Framework, keine Abhängigkeiten. Struktur:

**Konstanten**
```js
const API_BASE = '';   // relativ, kein hardcodierter Host
```

**Zustand**
```js
let currentResults = [];   // letzte Suchergebnisse
let selectedIndex = null;  // Index des gewählten Treffers
```

**Initialisierung**
```js
document.getElementById('searchForm').addEventListener('submit', async (e) => {
    e.preventDefault();
    await doSearch();
});
```

**`doSearch()`** – Hauptfunktion für Suchanfrage:
1. Eingabewert lesen, leere Eingabe → nichts tun
2. UI zurücksetzen: `resultsGrid`, `detailPanel`, `feedbackMsg` verstecken
3. `statusMsg` zeigen mit Text „Suche läuft …"
4. `searchBtn` deaktivieren
5. `fetch('/catalog/search?q=' + encodeURIComponent(query))`
6. Bei Erfolg:
   - `currentResults` befüllen
   - 0 Treffer → `statusMsg` mit „Keine Treffer für »{query}«" zeigen
   - >0 Treffer → `statusMsg` verstecken, `renderResults()` aufrufen
7. Bei Netzwerkfehler → `statusMsg` mit Fehlermeldung
8. `finally`: `searchBtn` wieder aktivieren

**`renderResults(results)`** – Trefferliste aufbauen:
- `resultsGrid` leeren und sichtbar machen
- Pro Treffer eine `.book-card` erzeugen via `innerHTML`:
  - Cover: `<img src="${r.coverUrl ?? 'placeholder.png'}" ...>` (Fallback auf leeres Bild bei null)
  - Titel, Autor
- Click-Handler pro Kachel: `selectBook(index)`

**`selectBook(index)`** – Treffer auswählen:
- Alle `.book-card` die Klasse `selected` entfernen
- Gewählte Kachel `.selected` hinzufügen
- `selectedIndex = index`
- `showDetail(currentResults[index])` aufrufen
- `feedbackMsg` zurücksetzen und verstecken

**`showDetail(book)`** – Detailansicht befüllen:
- `detailPanel` sichtbar machen
- `detailCover.src` setzen (Fallback: leerer String, sodass kein Broken-Image-Icon erscheint)
- `detailCover.alt` = Titel
- `detailTitle`, `detailAuthor`, `detailIsbn` befüllen (Fallback „–" bei null)
- `addBtn` aktivieren (nicht disabled)
- Panel per `scrollIntoView({ behavior: 'smooth', block: 'nearest' })` in den Viewport scrollen

**`addBtn` Click-Handler** – Buch übernehmen:
1. `addBtn` deaktivieren, Text → „Wird gespeichert …"
2. Ausgewähltes Buch aus `currentResults[selectedIndex]` lesen
3. `POST /catalog/books` mit JSON-Body (alle fünf Felder)
4. Bei 201: `feedbackMsg` grün zeigen: „✓ »{titel}« wurde zum Katalog hinzugefügt."
5. Bei 400: `feedbackMsg` rot zeigen mit `error`-Feld aus Response-JSON
6. Bei sonstigem Fehler: `feedbackMsg` rot mit generischer Meldung
7. `finally`: `addBtn` Text zurücksetzen, bei Fehler wieder aktivieren (bei Erfolg deaktiviert lassen – Doppel-Klick verhindern)

## Akzeptanzkriterien

- [ ] `search.html`, `search.js` und `catalog.css` liegen unter `src/main/resources/static/catalog/`.
- [ ] `http://localhost:8080/catalog/search.html` lädt ohne Fehler (kein 404, kein JS-Fehler in der Browser-Konsole beim Start).
- [ ] Eingabe eines Suchbegriffs (z. B. „Clean Code") und Klick auf „Suchen" zeigt Trefferkacheln mit Cover, Titel und Autor.
- [ ] Klick auf eine Kachel markiert sie mit einem blauen Rahmen und öffnet die Detailansicht darunter mit großem Cover, Titel, Autor und ISBN.
- [ ] Klick auf „In Katalog übernehmen" führt zu einer grünen Bestätigungsmeldung; der Button bleibt danach deaktiviert (kein Doppel-Eintrag).
- [ ] Eine Suche ohne Treffer zeigt „Keine Treffer für »…«" ohne JS-Fehler.
- [ ] Während der Suche ist der Button deaktiviert und eine Ladeanzeige sichtbar.
- [ ] Bücher ohne Cover (null `coverUrl`) zeigen kein kaputtes Bild-Icon.
- [ ] Enter-Taste im Suchfeld löst die Suche aus (via `form submit`).
- [ ] Die Navigationslinks „Buchsuche" und „Mein Katalog" sind sichtbar; „Buchsuche" ist optisch als aktiv markiert.
- [ ] Die bestehende Demo-Seite unter `/demo/demo.html` ist weiterhin erreichbar und funktioniert.
- [ ] `catalog.css` und `demo.css` haben keine gegenseitigen Abhängigkeiten (zwei eigenständige Stylesheets).
